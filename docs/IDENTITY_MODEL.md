# Identity Model

## Purpose

B1.1 establishes Tteeka's minimum multi-tenant identity foundation. It models merchant tenancy, globally identifiable staff users, and the membership relationship between them. It is a storage and integrity foundation only: it does not provide authentication, authorization, invitations, or identity APIs.

## Relationship model

```text
Merchant
    1
    |
    *
MerchantMembership
    *
    |
    1
User
```

One Merchant has many MerchantMemberships. One User has many MerchantMemberships. Each Merchant and User pair has at most one MerchantMembership.

`MerchantMembership` makes the relationship many-to-many: a merchant can have multiple staff users, and the same human user can work across multiple merchants. `User` therefore has no `merchantId`. Merchant-specific identity properties will belong on the membership or related merchant-scoped models rather than on the global user.

## Merchant

`Merchant` is the tenant and represents a business operating on Tteeka.

| Prisma field  | PostgreSQL column | Contract                                               |
| ------------- | ----------------- | ------------------------------------------------------ |
| `id`          | `id`              | UUID primary key, generated by PostgreSQL `uuidv7()`   |
| `displayName` | `display_name`    | Required human-facing name, `varchar(160)`             |
| `legalName`   | `legal_name`      | Optional legal name, `varchar(200)`                    |
| `phoneE164`   | `phone_e164`      | Optional canonical contact number, `varchar(16)`       |
| `email`       | `email`           | Optional contact email, `varchar(320)`                 |
| `currency`    | `currency`        | Required ISO-style three-character code, default `UGX` |
| `timezone`    | `timezone`        | Required IANA timezone, default `Africa/Kampala`       |
| `status`      | `status`          | `ACTIVE`, `SUSPENDED`, or `ARCHIVED`; default `ACTIVE` |
| `createdAt`   | `created_at`      | `timestamptz(3)`, default current time                 |
| `updatedAt`   | `updated_at`      | `timestamptz(3)`, maintained by Prisma                 |

The status index is `merchants_status_idx`.

## User

`User` represents one global human Tteeka staff identity, independent of any merchant.

| Prisma field  | PostgreSQL column | Contract                                                        |
| ------------- | ----------------- | --------------------------------------------------------------- |
| `id`          | `id`              | UUID primary key, generated by PostgreSQL `uuidv7()`            |
| `displayName` | `display_name`    | Required human-facing name, `varchar(160)`                      |
| `phoneE164`   | `phone_e164`      | Required, globally unique canonical E.164 number, `varchar(16)` |
| `email`       | `email`           | Optional and globally unique when present, `varchar(320)`       |
| `status`      | `status`          | `ACTIVE` or `DISABLED`; default `ACTIVE`                        |
| `createdAt`   | `created_at`      | `timestamptz(3)`, default current time                          |
| `updatedAt`   | `updated_at`      | `timestamptz(3)`, maintained by Prisma                          |

The database enforces `users_phone_e164_key` and `users_email_key`. PostgreSQL permits multiple null values in the email unique index. Future identity services must canonicalize E.164 phone numbers and normalize email values before writes; B1.1 deliberately adds no normalization service logic or `citext` extension.

The status index is `users_status_idx`.

## MerchantMembership

`MerchantMembership` represents one User belonging to one Merchant.

| Prisma field | PostgreSQL column | Contract                                             |
| ------------ | ----------------- | ---------------------------------------------------- |
| `id`         | `id`              | UUID primary key, generated by PostgreSQL `uuidv7()` |
| `merchantId` | `merchant_id`     | Required UUID foreign key to `merchants.id`          |
| `userId`     | `user_id`         | Required UUID foreign key to `users.id`              |
| `status`     | `status`          | `ACTIVE` or `DISABLED`; default `ACTIVE`             |
| `createdAt`  | `created_at`      | `timestamptz(3)`, default current time               |
| `updatedAt`  | `updated_at`      | `timestamptz(3)`, maintained by Prisma               |

`merchant_memberships_merchant_id_user_id_key` makes each `(merchant_id, user_id)` pair unique. Lookup indexes are `merchant_memberships_merchant_id_status_idx` and `merchant_memberships_user_id_status_idx`; the unique pair also supports merchant-and-user lookups.

Both foreign keys use `ON DELETE RESTRICT`. Tteeka changes lifecycle status instead of physically deleting a referenced Merchant or User, preserving membership history. Updates to referenced UUIDs use `ON UPDATE CASCADE`, although identifiers are not expected to change.

## Identifier and lifecycle decisions

All three primary keys are native PostgreSQL UUID columns with database-generated UUIDv7 defaults. Database generation makes the contract consistent for inserts performed inside or outside Prisma, while version 7 provides globally unique, time-ordered identifiers.

Lifecycle statuses are intentionally small:

- Merchant: `ACTIVE`, `SUSPENDED`, `ARCHIVED`
- User: `ACTIVE`, `DISABLED`
- MerchantMembership: `ACTIVE`, `DISABLED`

Status changes do not delete related records. No hard-delete API exists.

## Intentional omissions

Roles are absent from both User and MerchantMembership. A role is merchant-specific, not a global User property, and the role/permission model will be designed in a later reviewed checkpoint. B1.1 does not pre-encode owner, manager, sales, or other roles.

Passwords, password hashes, sessions, login, logout, verification, reset, and invitation workflows are also absent. Authentication is a separate checkpoint and must build on this identity foundation without weakening its tenancy or integrity rules.
